# BuildWise — Recommendation Module Data Contract

Use this document to generate integration-ready recommendation content for the existing BuildWise app.

**Do not rebuild the UI.** Fill or adapt content to these exact fields and IDs only.

**Source of truth in the codebase:**
- `src/features/buildwise/types.ts`
- `src/features/buildwise/recommendations.ts`
- UI consumers: `PlanHub` (cards), `Guide` (detail), `FinalPlan` / `Profile` (summary)

---

## 1. Planner input (`Answers`)

```ts
type Answers = {
  project?: string;
  location?: string;
  plot?: string;
  climate?: string;
  family?: string;
  outdoor?: string;
  future?: string;
  style?: string;
  priorities?: string[]; // max 3
};
```

### Allowed values

| Field | Allowed values |
|-------|----------------|
| `project` | `Build a new home`, `Renovate`, `Redesign` |
| `location` | `Karachi`, `Lahore`, `Islamabad`, `Other` |
| `plot` | `Under 5 marla`, `5–10 marla`, `10–20 marla`, `1 kanal or more` |
| `climate` | `Intense heat`, `Humidity`, `Monsoon rains`, `Dust & haze`, `Mild seasons` |
| `family` | `1–2 people`, `3–5 people`, `6+ people` |
| `outdoor` | `Every day`, `On weekends`, `Occasionally` |
| `future` | `A growing family`, `Working from home`, `Parents moving in`, `No major changes` |
| `style` | `Modern`, `Traditional`, `Minimal`, `Cultural` |
| `priorities` | up to 3 of: `Natural light`, `Ventilation`, `Energy efficiency`, `Privacy`, `Space`, `Aesthetics` |

## 3. Per-topic content (`TopicContent`)

This is what the Guide screen and Plan cards render.

```ts
type TopicContent = {
  id: TopicId;
  number: string;       // "01" … "06"
  title: string;        // short internal/display name
  cardTitle: string;    // PlanHub card heading
  blurb: string;        // 1-line card description
  label: string;        // small uppercase eyebrow, e.g. "Climate & comfort"
  hero: string;         // large Guide headline (can be personalised)
  why: string;          // “Why this matters” paragraph (can be personalised)
  discuss: string[];    // usually 4 bullets: “Things worth discussing”
  tip: string;          // BuildWise tip quote (no surrounding curly quotes needed in data)
  planLabel: string;    // Final plan list label, e.g. "Natural Ventilation"
};
```

### UI field mapping

| Field | Where it appears |
|-------|------------------|
| `label` | Guide eyebrow |
| `hero` | Guide H1 |
| `why` | Guide “Why this matters” |
| `discuss[]` | Guide numbered list |
| `tip` | Guide tip blockquote |
| `number` | PlanHub card index |
| `cardTitle` | PlanHub card title |
| `blurb` | PlanHub card subtitle |
| `planLabel` | Final plan discuss list |

## 4. Catalog templates (before personalisation)

In `topicCatalog`, static fields are stored plus:

```ts
heroTemplate: string; // filled → TopicContent.hero
whyTemplate: string;  // filled → TopicContent.why
```

### Supported placeholders in templates

- `{location}`
- `{climate}`
- `{style}`
- `{plot}`
- `{family}`
- `{outdoor}`
- `{future}`

Example:

```text
In {location}, plot orientation shapes which rooms catch morning light…
```

## 5. Engine output (`BuiltPlan`)

```ts
type BuiltPlan = {
  greetingName: string;
  profileStrip: string;                 // e.g. "Karachi · Build a new home · Modern · 3–5 people"
  profileRows: Array<[string, string]>; // Profile screen label/value rows
  topTopicId: TopicId;
  topTitle: string;                     // featured recommendation title
  topSummary: string;                   // featured recommendation body
  topics: TopicContent[];               // ranked list (all 6 topics)
  discussList: string[];                // usually planLabel values for FinalPlan
  planText: string;                     // plain text for Save / Share download
};
```

Generated by: `buildPlan(answers: Answers): BuiltPlan`

Helpers also used by UI:
- `getTopic(id, answers): TopicContent`
- `nextTopicId(current, plan): TopicId`

## 8. What to produce for integration

Return content that can drop into `topicCatalog` / `buildPlan` without changing components:

1. For each of the 6 `TopicId`s: full `TopicContent`-compatible fields (`cardTitle`, `blurb`, `label`, `heroTemplate`, `whyTemplate`, `discuss` [4 items], `tip`, `planLabel`).
2. Keep `id` and `number` exactly as listed.
3. Use only the placeholders listed above in templates.
4. Optionally: richer `topSummary` patterns that still fit a single string.
5. Do **not** add new TopicIds, new required UI sections, API calls, or auth.

### Preferred output format

Provide a TypeScript object matching:

```ts
Record<TopicId, {
  id: TopicId;
  number: string;
  title: string;
  cardTitle: string;
  blurb: string;
  label: string;
  heroTemplate: string;
  whyTemplate: string;
  discuss: string[];
  tip: string;
  planLabel: string;
}>
```

Tone: premium, calm, editorial, Pakistan residential context. Short readable copy. Prototype/dummy guidance only — not engineering certification.
